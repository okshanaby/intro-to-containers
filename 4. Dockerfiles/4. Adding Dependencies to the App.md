## Adding Dependencies (npm install) to Docker

### 1. Upgrade the App: Use a Real Framework

Instead of a basic HTTP server, you now use a more realistic Node.js app with a framework. This example uses Fastify, a popular backend framework similar to Express.

```js
const fastify = require("fastify")({ logger: true });

fastify.get("/", function handler(request, reply) {
  reply.send({ hello: "world" });
});

fastify.listen({ port: 8080, host: "0.0.0.0" }, (err) => {
  if (err) {
    fastify.log.error(err);
    process.exit(1);
  }
});
```

**This app:**

- Creates a web server
- Responds with JSON `{ hello: "world" }`
- Runs on port `8080`
- Uses `0.0.0.0` so it’s accessible outside the container

### 2. Initialize Project and Install Dependencies

Since this app uses external libraries, you need to install them.

**Run:**

```sh
npm init -y
npm install fastify
```

**This creates:**

- `package.json` → project info + dependencies
- `package-lock.json` → exact versions
- `node_modules/` → installed packages

### 3. Test Locally First

Before Docker, make sure everything works.

`node index.js`

**Open:**
- http://localhost:8080
- You should see JSON response
- Logs appear in terminal

### 4. Why It Fails in Docker (Important)

If you try to run this inside Docker now, it will fail because:

- Dependencies are **not installed inside the container**
- `node_modules` is usually **not copied**

Containers must install dependencies themselves


### 5. Add Dependency Installation (RUN)

You fix this by adding a `RUN` instruction to install dependencies during build.

**Updated Dockerfile:**

```dockerfile
FROM node:20

USER node

WORKDIR /home/node/code

COPY --chown=node:node . .

# RUN npm install
RUN npm ci

CMD ["node", "index.js"]
```

- `COPY --chown=node:node . .` - Copies all project files into container

- `RUN npm ci` - Installs dependencies inside container.

**Why npm ci instead of npm install:**

- Uses `package-lock.json` exactly
- Faster and more predictable
- Deletes existing `node_modules`
- Ideal for **production builds**

### 7. Ignore Unnecessary Files (.dockerignore)

You should prevent copying unnecessary files like node_modules.

**Create `.dockerignore`:**

```.dockerignore
node_modules/
.git/
```

**Why:**

- Reduces image size
- Avoids conflicts
- Ensures clean installs

### 8. Permission Problem (Common Issue)

Sometimes builds fail due to permissions.

**Problem:**

- `WORKDIR` may create directories as **root**
- But you're using `USER node`
- Node user can’t modify root-owned directories

### 9. Fix Permissions Properly

Instead of relying on `WORKDIR`, explicitly create the directory as the correct user.

**Final Improved Dockerfile:**

```dockerfile
FROM node:20

USER node

# explicit create directory
RUN mkdir /home/node/code 

WORKDIR /home/node/code

COPY --chown=node:node . .

RUN npm ci

CMD ["node", "index.js"]
```

### 10. Build and Run the Container

**Build:**

```sh
docker build -t more-complicated-app .
```

**Run:**

```sh
docker run -it -p 8080:8080 --name my-app --rm --init more-complicated-app
```

- `-p 8080:8080` → expose port
- `--init` → proper shutdown
- `--rm` → auto cleanup

**Key Takeaways**
- Containers must install their own dependencies
- Use `.dockerignore` to keep builds clean
- Prefer `npm ci` for consistency
- Always handle permissions correctly
- Use `0.0.0.0` for container networking
- `npm ci` follows the `package-lock.json` strictly, verifies checksums, and fails if there are any issues, unlike `npm install` which can ignore inconsistencies
