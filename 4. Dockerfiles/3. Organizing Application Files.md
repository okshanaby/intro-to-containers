### 1. Problem: Running as Root (Unsafe)

By default, Docker containers run as the **root user**, and your app is placed in the root directory. While this works, it’s not safe.

If a vulnerability is found in your Node.js app:

- An attacker would gain **root access inside the container**
- Root can:
  - modify files
  - install software
  - potentially escape or damage the system

This is why running as root is considered **bad practice**

### 2. Solution: Use a Non-Root User

To improve security, you should run your app as a normal user instead of root. The `node:20` image already provides a user called `node`, so you don’t need to create one manually.

Updated Dockerfile:

```Dockerfile
FROM node:20

USER node

COPY index.js /home/node/code/index.js

CMD ["node", "/home/node/code/index.js"]
```

Explanation:
- `USER node` - Switches from root → node user
- `/home/node/` - home directory of node user
- App now runs with **limited permissions**
- Reduces risk if the app is compromised

Instead of putting files in the root directory, you store them inside the user’s home directory.

We could make our own user too using bash by adding `RUN useradd -ms /bin/bash lolcat` to add a `lolcat` user

### 3. Fix File Ownership with --chown

When copying files, they are owned by root by default. This can cause permission problems when running as another user.

Fix:

```Dockerfile
COPY --chown=node:node index.js /home/node/code/index.js
```

Explanation:

- First `node` → user
- Second `node` → group
- Ensures the file is owned by the correct user

### 4. Improve Readability with WORKDIR

Right now, paths are long and repetitive. You can simplify this using `WORKDIR`.

Improved Dockerfile:

```Dockerfile
FROM node:20

USER node

WORKDIR /home/node/code

COPY --chown=node:node index.js .

CMD ["node", "index.js"]
```

`WORKDIR` sets the current working directory inside the container, similar to running `cd` in a terminal.

- All paths become relative to this directory
- If the directory doesn’t exist → Docker creates it
- `.` means ***“current directory”*** (/home/node/code)
- File keeps the same name (index.js)
- You could rename it if needed: `COPY index.js app.js`

**Key Takeaways**
- Don’t run containers as **root**
- Use existing users like `node`
- Store files in a **home directory**
- Fix permissions using `--chown`
- Use `WORKDIR` to simplify paths
- Prefer `COPY` over `ADD`

**Notes:**
`ADD` has additional features like adding remote URLs and automatically unzipping files, `COPY` is simpler and more straightforward. The recommendation is to use `COPY` unless you specifically need the extra functionality of `ADD`.

You can create a custom user using the `useradd` command with flags like` -ms /bin/bash`, which creates a new user with a home directory and sets the default shell. For example: `useradd -ms /bin/bash username`.
