## Introduction to Dockerfiles

A Dockerfile is a text file that contains instructions on how to build a Docker image. Each line in the file represents a step that modifies the container.

- Instructions are usually written in uppercase (convention)
- Each instruction creates a new layer
- Layers are stacked to form the final image

### 1. Creating Your First Dockerfile

To start, you need a project folder with a file named Dockerfile (no extension). This file will contain the instructions for building your container.

- Create a new folder
- Inside it, create a file named exactly: `Dockerfile`

### 2. Writing the Dockerfile

The simplest possible Dockerfile starts from an existing image and defines what should run when the container starts.

```Dockerfile
FROM node:20

CMD ["node", "-e", "console.log(\"hi lol\")"]
```

The `FROM` instruction tells Docker which base image to use. In this case, it uses a Node.js environment. The `CMD` instruction defines the command that runs when the container starts.

- `FROM node:20` - Uses an existing Node.js image
- `CMD [...]` - Runs a command when the container starts

Only one CMD is active in a Dockerfile. If multiple are defined, Docker will use the last one.

### 3. Understanding Layers and Base Images

When Docker builds an image, each instruction creates a new layer. These layers are cached and reusable.

- Each step = one layer
- Each layer has its own image ID (hash)
- Layers improve efficiency and reuse

The base image (`node:20`) is not built from scratch. It is built on top of other images, eventually tracing back to a minimal operating system like Debian.

- Images build on top of other images
- You don’t need to manually install everything
- You reuse community-built environments

### 4. Building the Image

To build your container image, run the build command inside the folder containing your Dockerfile.
```sh
docker build .
```

Docker will:
- Read the Dockerfile
- Execute each instruction step-by-step
- Create layers for each step
- Output a final image ID

### 5. Running the Container
Once built, you can run the container using the image ID.

```sh
docker run <IMAGE_ID>
```

This will execute the command defined in CMD.

### 6. Tagging Images (Naming)

Using image IDs is inconvenient, so Docker allows you to assign names (tags) to images.

```sh
docker build -t my-node-app .
docker run my-node-app
```

- `-t` means “tag”
- Makes images easier to reference

### 7. Versioning Images

You can create different versions of the same image by using tags.
```sh
docker build -t my-node-app:1 .
docker run my-node-app:1
```

If you modify the Dockerfile:

```js
console.log("wat")
```

Then build a new version:

```sh
docker build -t my-node-app:2 .
docker run my-node-app:2
```

You can still run the older version:

```sh
docker run my-node-app:1
```

- Helps track changes
- Allows rollback to previous versions

### Summary

Building Docker containers allows you to define and control your runtime environment. By using Dockerfiles, you can create reusable, versioned, and disposable containers that build on top of existing images.

- Start from a base image
- Add your own instructions
- Build → run → tag → version
- Keep containers disposable and reproducible
