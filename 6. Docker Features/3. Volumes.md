## What is a Volume?

A volume is:

> Storage managed by Docker itself.

Unlike bind mounts:

- you don’t manage the folder directly
- Docker manages it for you
  
### Simple Difference

**Bind Mount**

`Your computer folder → container`

Example:

`/home/okasha/project`

You can see and edit files directly.

Good for:

- development
- live editing
- configs

**Volume**

`Docker-managed storage → container`

Docker stores it somewhere hidden internally.

Good for:

- databases
- persistent app data
- container state

### Why Volumes Exist

Imagine a database container:

```sh
docker run postgres
```

If container dies: database gone. Bad.

Instead:

```sh
docker run --mount type=volume ...
```

Now data survives even after container deletion.

### The Example App

The Node.js app is a simple counter.

Every time it runs:

1. Read number from file
1. Print number
1. Increase number
1. Save updated number

### Understanding index.js

```js
const fs = require("fs").promises;
const path = require("path");

// Use DATA_PATH if provided. Otherwise use: ./data.txt
const dataPath = path.join(process.env.DATA_PATH || "./data.txt");

// Read the File
fs.readFile(dataPath)
  .then((buffer) => {

    // Convert file to text:
    const data = buffer.toString();
    console.log(data);

    // Increase it:
    writeTo(+data + 1);
  })
  .catch((e) => {
    console.log("file not found, writing '0' to a new file");

    // Creates file with: 0
    writeTo(0);
  });

const writeTo = (data) => {
  fs.writeFile(dataPath, data.toString()).catch(console.error);
};
```


### Dockerfile

```dockerfile
FROM node:20-alpine
WORKDIR /node/src
COPY --chown=node:node . .
CMD ["node", "index.js"]
```

### Build Container

```sh
docker build -t incrementor .
```

Creates image named: incrementor

### Run WITHOUT `Volume`

```sh
docker run --rm incrementor
```

Output every time:  `file not found, writing '0'`

WHY?

Because:

- container starts fresh every run
- file disappears when container exits

> Even though app writes data: container deletes it afterward.

### Why `--rm` Matters

Means: remove container after it finishes

Container fully disappears.

### Now Add a Volume

```sh
docker run --rm \
  --env DATA_PATH=/data/num.txt \
  --mount type=volume,src=incrementor-data,target=/data \
  incrementor
```

Now data survives.

### Step-by-Step Breakdown

**`--env DATA_PATH=/data/num.txt`**

- Creates environment variable: `DATA_PATH=/data/num.txt`
- So app stores number here: `/data/num.txt` inside container.

**`--mount`**

Mount storage into container.

**`type=volume`**

Use Docker-managed storage.

**`src=incrementor-data`**

- Volume name.
- Docker creates it automatically.
- Think of it like: Docker hard drive
- Named: `incrementor-data`

**`target=/data`**

Mount volume into:

`/data`

inside container.

### What Happens Now

First run:

```sh
file not found
writes 0
```

Second run:

```sh
0
writes 1
```

Third run:

```sh
1
writes 2
```

Fourth run:

```sh
2
writes 3
```

The data survives because volume survives.

Even if container dies:

### Important Concept

**Container Storage**

- Temporary.
- Destroyed with container.

**Volume Storage**

- Persistent.
- Independent from container lifecycle.

### Anonymous vs Named Volumes
   
**Named Volume**
`src=incrementor-data`

- Easy to reuse later.

**Anonymous Volume**

- If you omit `src=`: Docker creates random volume name.
- Example: `a82f91cbb12...`
- Harder to reuse/manage.

### Why Docker Recommends Volumes

Docker can:

- manage storage
- isolate data
- backup volumes
- improve security
- avoid permission issues

With bind mounts:

- you manage everything yourself

### Real-World Examples
