## Networking with Docker
Docker networking allows multiple containers (like a Node.js app and MongoDB database) to communicate with each other using container names over a shared virtual network.

### Containers can talk to each other using Docker networking.

Before, your app was just:

- one container
- one app
- completely self-contained

But real applications are usually made of multiple services:

`Frontend -> Backend -> Database`

Example:

- Node.js app
- MongoDB database
- Redis cache
- Nginx proxy

These are often separate containers.

So the question becomes:

How do containers communicate?

Answer: **Docker networking**

### The Main Idea

Instead of putting MongoDB inside the same container as your app:

❌ Bad approach:

One huge container:
- Node.js
- MongoDB
- Everything together

✅ Better approach:

- Container 1 = Node.js app
- Container 2 = MongoDB

- This is cleaner and more modular.

But now they must communicate over a network.

### Docker Networks

Docker creates virtual networks.

Containers connected to the same network can:

- see each other
- communicate
- use container names like hostnames

Think of it like:

Wi-Fi network for containers

### Existing Docker Networks

When you run:

```sh
docker network ls
```

You see networks like:

| Network | Meaning                               |
| ------- | ------------------------------------- |
| bridge  | default Docker network                |
| host    | uses your computer’s network directly |
| none    | no networking                         |

### Why Create Our Own Network?

Docker recommends creating your own custom network instead of using the default bridge.

So we create:
```sh
docker network create --driver=bridge app-net
```

Meaning:

- create a bridge network
- call it app-net

- Now containers can join this network.

### Starting MongoDB Container
```sh
docker run -d --network=app-net -p 27017:27017 --name=db --rm mongo:7
```

Let’s break this down.

#### `-d`

- Run in background.

#### `--network=app-net`

- Attach container to our custom network.
- Now other containers on app-net can reach it.

#### `-p 27017:27017`

- Expose MongoDB port.
- MongoDB uses port 27017.

#### `--name=db`

- This gives the container a hostname: `db`
- Other containers can now connect using: `mongodb://db:27017`

This is Docker DNS magic.

#### `--rm`

Automatically delete container after stopping.

Without this:

- stopped containers remain
- names stay reserved
- logs remain

With `--rm`:

- clean automatic removal

### Testing Container-to-Container Communication

This command starts another MongoDB container:

```sh
docker run -it --network=app-net --rm mongo:7 mongosh --host db
```

This container:

- joins the same network
- runs Mongo shell client
- connects to host db

And `db` is our first MongoDB container.

So:

`Container A -> Container B`

This proves networking works.

### Node.js App

Now the Node app connects to MongoDB.

```js
const fastify = require("fastify")({ logger: true });
const { MongoClient } = require("mongodb");
const url = process.env.MONGO_CONNECTION_STRING || "mongodb://localhost:27017";
const dbName = "dockerApp";
const collectionName = "count";

async function start() {
  const client = await MongoClient.connect(url);
  const db = client.db(dbName);
  const collection = db.collection(collectionName);

  fastify.get("/", async function handler(request, reply) {
    const count = await collection.countDocuments();
    return { success: true, count };
  });

  fastify.get("/add", async function handler(request, reply) {
    const res = await collection.insertOne({});
    return { acknowledged: res.acknowledged };
  });

  fastify.listen({ port: 8080, host: "0.0.0.0" }, (err) => {
    if (err) {
      fastify.log.error(err);
      process.exit(1);
    }
  });
}

start().catch((err) => {
  console.log(err);
  process.exit(1);
});
```

Important line:

```ts
const url =
  process.env.MONGO_CONNECTION_STRING ||
  "mongodb://localhost:27017";
```

Meaning:

- Use environment variable if provided
- otherwise Use localhost

This makes the app flexible.

### Why `localhost` Changes

This part confuses many beginners.

Inside a container:

`localhost = THAT SAME CONTAINER`

NOT your computer.

So inside the Node container:

`localhost != MongoDB container`

That’s why we use:

`mongodb://db:27017`

Because db is the MongoDB container name on the Docker network.

### Running the Node App

```dockerfile
FROM node:20

USER node

RUN mkdir /home/node/code

WORKDIR /home/node/code

COPY --chown=node:node package-lock.json package.json ./

RUN npm ci

COPY --chown=node:node . .

CMD ["node", "index.js"]
```

Build image:

```sh
docker build --tag=my-app-with-mongo .
```

Run container:

```sh
docker run \
-p 8080:8080 \
--network=app-net \
--init \
--env MONGO_CONNECTION_STRING=mongodb://db:27017 \
my-app-with-mongo
```

### Important Parts

**`--network=app-net`**

Now Node app joins same network as MongoDB.

Without this:

- they cannot communicate.

**`--env MONGO_CONNECTION_STRING=mongodb://db:27017`**

Environment Variable

This tells Node app:

> "MongoDB lives at container named db"

### App Endpoints

**`/add`**

Adds document into MongoDB.

`Database count increases`

**`/`**

Returns document count.

Example:

```json
{
  "success": true,
  "count": 5
}
```

### Big Concept Learned Here

You now have:

`Node.js container <-> MongoDB container`

communicating over Docker networking.

This is how most real systems work.

### Important Warning About Data

MongoDB data currently lives INSIDE the container.

If container dies:

- Data disappears

because containers are temporary.

### Solution: Volumes

You attach a volume:

`MongoDB container -> Docker Volume`

Then data survives container restarts.

This is why databases almost always use volumes.
