## What is a Bind Mount?

A bind mount is a way to share files from the local host machine directly into a container, allowing developers to run containers using local files without rebuilding the container every time. It creates a 'portal' between the local computer and the container, enabling stateful development and file sharing.

A bind mount means:

***“Take a folder from my computer and connect it into the container.”***

So the container can read/write your real files.

### Practical use case for bind mounts during development

A practical use case is running a development server, such as a Node.js application or a static website, where developers can make local file changes and immediately see those changes reflected in a containerized environment without needing to rebuild the container.

### Real Example with NGINX

Normally:

- you build a custom Docker image
- copy your website into it

But for quick local testing, that’s annoying.

Instead:

- use the official NGINX container
- connect your website folder into it
  
**The Command**

```sh
docker run \
  --mount type=bind,source="$(pwd)"/dist,target=/usr/share/nginx/html \
  -p 8080:80 \
  nginx:latest
```

### Step-by-Step Breakdown

**Step 1 — `docker run`**

Starts a container.

**Step 2 — `--mount`**

Tells Docker:

“I want to connect something from my computer.”

**Step 3 — `type=bind`**

Means:

use an existing folder from the host computer

There are 2 common types:

- `bind`
- `volume`

Here we use `bind`.

**Step 4 — `source="$(pwd)"/dist`**

This is the folder on YOUR computer.

Example:

```sh
/home/okasha/myapp/dist
```

`$(pwd)` means:

current folder path

So Docker gets the absolute path.

Docker requires absolute paths.

**Step 5 — `target=/usr/share/nginx/html`**

This is INSIDE the container.

NGINX serves websites from:

```sh
/usr/share/nginx/html
```

So we replace that folder with our local `dist` folder.

**Step 6 — `-p 8080:80`**

Port mapping.

Meaning:

| Host | Container |
| ---- | --------- |
| 8080 | 80        |

So you open:

```sh
localhost:8080
```

and access NGINX.

**Step 7 — `nginx:latest`**

Use the official NGINX image.

### What Actually Happens

Without bind mount:

`Container has its own files`

With bind mount:

`Your computer folder ↔ container folder`

They become connected.

If you change files on your computer:

- NGINX sees updates immediately

Very useful for development.

### Key difference between a bind mount and a container's default file system

In a container's default file system, data is self-contained and disappears when the container is destroyed. With a bind mount, files are shared from the host machine, allowing data persistence and direct interaction between the local file system and the container.
