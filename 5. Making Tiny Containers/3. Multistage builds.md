## Multi-Stage builds
You don’t need everything in production that you needed to build the app.

So:

- Use a big image to build (with npm, compilers, etc.)
- Use a small image to run (only what’s necessary)

Purpose:

To create separate stages for building and production, allowing reduction of final container size by removing unnecessary dependencies and build tools like NPM, and potentially improving security by isolating build-specific operations

### What is a Multi-stage Build?

A Dockerfile with **multiple** `FROM` lines.

Each `FROM` = a separate stage.

Only the **last stage** becomes your final image.

### Stage 1: Build Stage

```dockerfile
FROM node:20 AS node-builder
RUN mkdir /build
WORKDIR /build
COPY package-lock.json package.json ./
RUN npm ci
COPY . .
```

What’s happening:
- `FROM node:20 AS node-builder`
  - Full Node.js image (includes npm and everything)
  - Named `node-builder` so we can reference it later
- `npm ci` - Installs dependencies (needed to build your app)
- `COPY . .` - Copies your entire app code

This stage is **only for building**, not for running.

### Stage 2: Runtime Stage

```dockerfile
FROM alpine:3.19
RUN apk add --update nodejs
RUN addgroup -S node && adduser -S node -G node
USER node
RUN mkdir /home/node/code
WORKDIR /home/node/code
COPY --from=node-builder --chown=node:node /build .
CMD ["node", "index.js"]
```

What’s happening:
- `FROM alpine:3.19` - Very small Linux image
- `apk add --update nodejs` - Install only Node.js, not npm
- `USER node` - Run as non-root (better security)
- `COPY --from=node-builder /build .` 
  - Copy built app from Stage 1
  - This is the key part of multi-stage builds
- CMD ["node", "index.js"] - Start the app

This stage is what actually runs in production.

### Key Insight

You **used npm to build**, but you **don’t include npm in the final image**.
