## 3. Namespaces

Linux namespaces isolate what a process can see and interact with. While `chroot` only changes the visible filesystem root, namespaces isolate things like process IDs, mounts, networking, hostnames, and user identities. This is one of the core building blocks of containers.<br>

`unshare` - Create a new namespace and run a process inside it.<br>

#### Why `chroot` alone is not enough

With `chroot`, the filesystem is mostly isolated, but processes outside the jail can still be visible and affected.<br>

- Terminal `#1` - Enter the `chroot` environment.
- Terminal `#2` - Run `docker exec -it docker-host bash` to open another shell in the same container.
- In terminal `#2`, run `tail -f /my-new-root/secret.txt &` - Start a long-running background process.
- In terminal `#2`, run `ps` - Find the PID of the `tail` process.
- In terminal `#1`, run `kill <PID>` - You can kill the process that was started outside the `chroot`.

This shows that `chroot` is not full isolation. It changes the filesystem view, but it does not isolate the process table. Namespaces add that missing isolation.<br>

#### 1. Install the tool: Build a better root filesystem

Exit the current `chroot` shell first if you are still inside it.<br>

**Note:** The next step downloads roughly 150 MB and can take a few minutes. Unlike Docker image layers, `debootstrap` does not provide the same caching experience.<br>

```sh
apt-get update -y # Refresh package metadata
apt-get install debootstrap -y # Install the tool used to build a minimal Ubuntu userspace
```

#### 2. Create a minimal Ubuntu system

```sh
debootstrap --variant=minbase jammy /better-root
```

**Flags:**<br>

- `--variant=minbase` - Build a minimal Ubuntu system.
- `jammy` - Use Ubuntu 22.04.
- `/better-root` - Install the filesystem into this directory.

This creates a fresh minimal Ubuntu root filesystem that we can enter with stronger isolation than plain `chroot`.<br>

#### 3. Enter that system with namespaces (like entering a container)

```sh
unshare --mount --uts --ipc --net --pid --fork --user --map-root-user chroot /better-root bash
```

**Flags:**<br>

- `--mount` - Create a separate mount namespace.
- `--uts` - Create a separate hostname/domain namespace.
- `--ipc` - Create a separate inter-process communication namespace.
- `--net` - Create a separate network namespace.
- `--pid` - Create a separate process ID namespace.
- `--fork` - Fork before launching the process so PID isolation works correctly.
- `--user` - Create a separate user namespace.
- `--map-root-user` - Map your current user to `root` inside the new namespace.

This command does two things:

- `chroot /better-root bash` - Changes the visible root filesystem to `/better-root` and starts `bash`.
- `unshare ...` - Creates isolated namespaces so the shell gets its own view of processes, mounts, networking, and more.

In practice, this feels much closer to a real container because the shell now runs inside an isolated environment instead of only a different root directory.<br>

#### 4. Mount required system filesystems

After entering the new environment, run:<br>

```sh
mount -t proc none /proc # Mount process metadata so tools like `ps` work properly.
mount -t sysfs none /sys # Mount kernel and device information.
mount -t tmpfs none /tmp # Provide a temporary in-memory filesystem.
```

Without these mounts, many commands inside the isolated environment will not behave correctly.<br>

#### Test the isolation again

- In terminal `#2`, run `tail -f /my-new-root/secret.txt &`.
- In the `unshare` + `chroot` shell, run `ps`.
- Try `kill <PID>` for the process from terminal `#2`.

This time it should not work because the new shell has its own PID namespace and cannot see or control processes outside that namespace.<br>

**Notes:**<br>

Namespaces are one of the main reasons containers feel isolated even though they share the same kernel. They let each container have its own view of resources like processes, networking, and mounts.<br>

The `--user --map-root-user` combination is especially important because it lets you appear as `root` inside the namespace without giving you unrestricted root access outside of it.<br>

`chroot` changes where the filesystem starts, but namespaces control what the process can see. Together, they form a much stronger foundation for container-like isolation.<br>
