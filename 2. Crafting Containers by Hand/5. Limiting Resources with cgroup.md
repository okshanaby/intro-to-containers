## 5. Limiting Resources with cgroup

You’re learning cgroups → a Linux feature that lets you limit resources (like RAM and CPU) for a group of processes.

Let's get a third terminal going. From your host OS run another `docker exec -it docker-host bash`

You’re using 3 terminals to observe and control what’s happening:

🖥️ What each terminal is doing
Terminal #1 → inside the isolated environment (your “mini-computer”)
Terminal #2 → control panel (you manage processes here)
Terminal #3 → monitoring (you watch CPU & RAM using htop)

`htop` - a system resource monitoring terminal ui tool

**Terminal #3**
```sh
# 1. Install and run htop 
apt-get install htop
htop
```

### Limiting memory

**Terminal #1**
```sh
# 2. Run a “stress” command
yes | tr \n x | head -c 1048576000 | grep n
```
👉 What this does:
- yes → endlessly outputs text
- Pipes + transforms → keeps CPU busy
- head -c 1048576000 → tries to use ~1GB of memory

💥 Result:
- CPU goes to 100%
- RAM usage shoots up (~1GB)

You’ll see this in htop (Terminal 3).

**Terminal #2**
```sh
# 3. Stop the yes process (you can get the PID from htop) to stop the CPU from being pegged and memory from being consumed
kill -9 <PID of yes>

# 4. Check memory limit
cat /sys/fs/cgroup/sandbox/memory.max
```
If it says something like max, it means:
- No memory limit
- The process can use all available RAM
```sh
# 5. Set memory limit (80MB)
echo 83886080 > /sys/fs/cgroup/sandbox/memory.max
```

**Terminal #1**
```sh
#6. Run the stress command again
yes | tr \n x | head -c 1048576000 | grep n
```

But now:
- It can’t reach 1GB anymore
- It gets capped at 80MB
- CPU usage also drops because it can’t allocate more memory


### Limiting CPU

**Terminal #1**
```sh
# this will peg one core of a CPU at 100% of the resources available, see it peg 1 CPU in terminal 3
yes > /dev/null
```

**Terminal #2**
```sh
# from #2, (you can get the PID from htop) to stop the CPU from being pegged
kill -9 <PID of yes>
```
What happens:
- `yes` = generates infinite output
- `> /dev/null` = throws output away (so disk isn’t affected)
- CPU is used 100% just to keep generating text

```sh
# from #2 this allows the cgroup to only use 5% of a CPU
echo '5000 100000' > /sys/fs/cgroup/sandbox/cpu.max

```

*What `cpu.max` means*

It has two numbers:
```sh
quota  period
5000   100000
```
Meaning:
- 100000 µs = 100ms window
- Within every 100ms:
- process is allowed to run for 5000 µs = 5ms

🔥 Convert that to human meaning
- 5ms / 100ms = 5%

👉 So you're saying:
“This container can only use 5% of a CPU core.”

### Limiting Process
One more demo, the dreaded `fork bomb`. A fork bomb is a script that forks itself into multiple processes, which then fork themselves, which then fork themselves, etc., until all resources are consumed and it crashes the computer. It can be written plainly as
```sh
fork() {
    fork | fork &
}
fork
```
but you'll see it written as `:(){ :|:& };:` where `:` is the name of the function instead of fork.

So someone could run a fork bomb on our system right now and it'd limit the blast radius of CPU and RAM but creating and destroying so many processes still carries a toll on the system. What we can do to more fully prevent a fork bomb is limit how many PIDs can be active at once. Let's try that.

**Terminal #2**
```sh
# See how many processes the cgroup has at the moment
cat /sys/fs/cgroup/sandbox/pids.current

# See how many processes the cgroup can create before being limited (max)
cat /sys/fs/cgroup/sandbox/pids.max

# set a limit that the cgroup can only run 3 processes at a time
echo 3 > /sys/fs/cgroup/sandbox/pids.max

# this runs 5 15 second processes that run and then stop. run this from within #2 and watch it work. now run it in #1 and watch it not be able to. it will have to retry several times
for a in $(seq 1 5); do sleep 15 & done

# DO NOT RUN THIS ON YOUR COMPUTER. This is a fork bomb. If not accounted for, this would bring down your computer. However we can safely run inside our #1 because we've limited the amount of PIDs available. It will end up spawning about 100 processes total but eventually will run out of forks to fork.
:(){ :|:& };:
```
