## 2. Chroot

The `chroot` command allows a Linux process to only see a specific directory and its subdirectories, effectively creating an isolated environment where the process can only access files within that root directory. This is also known as a ***Linux jail*** or a ***jailed process***.<br>

`chroot` - Change root; choose the root folder of your shell.<br>

`docker ps` - Show running Docker images/processes.<br>

#### Creating custom Docker

```sh
docker run -it --name docker-host --rm --privileged ubuntu:jammy
``` 
<br>

**Flags:**<br>

- `docker run` - Run the image.
- `-it` - Interactive mode.
- `--name` - Name of the Docker image.
- `--rm` - Removes / deletes everything after exiting or killing the container.
- `--privileged` - Gives root privileged.
- `ubuntu:jammy` - Ubuntu image, Jammy.

#### Inside `ubuntu:jammy`

`root@0fb4cb65e1f9:/#`<br>

```sh
cat /etc/issue # Shows running OS / image version.

mkdir my-new-root # Creates my custom root directory.

echo "My secret key" >> ./my-new-root/secrete.txt # Create `secrete.txt` and save the string in it.

chroot ./my-new-root/ bash # Change root to that directory, `bash` as interpreter. Fails because `bash` is not there yet; you have to copy it in.

which bash # Shows where `bash` runs from (`/bin/bash` or `/usr/bin/bash`).

ldd /usr/bin/bash # Shows libraries / dependencies for `bash` (e.g. `lib` and `lib64`). Helps identify necessary library dependencies

mkdir ./my-new-root/lib # Creates `lib` folder in the new root.

mkdir ./my-new-root/lib64 # Creates `lib64` folder in the new root.

cp /lib/x86_64-linux-gnu/libtinfo.so.6 /lib/x86_64-linux-gnu/libc.so.6 ./my-new-root/lib # Copy the `bash` libs into the new-root `lib`.

cp /lib64/ld-linux-x86-64.so.2 ./my-new-root/lib64/ # Copy the `bash` `lib64` into the new-root `lib64`.

mkdir ./my-new-root/bin # Creates `bin` folder for executables.

cp /usr/bin/bash my-new-root/bin/ # Copy the `bash` binary into the new-root `bin`.

chroot my-new-root/ bash # Change the root / shell to `new-root` with `bash` as interpreter (this time it works).

```
<br>

**Notes:**<br>

When copying a binary like `bash`, you must also copy all of its dependent libraries (similar to Windows DLLs). These libraries are required for the binary to function properly in the new root environment. The `ldd` command helps identify these necessary library dependencies.<br>

The `-it` flags make the container interactive. Specifically, `-i` keeps `STDIN` open, and `-t` allocates a `pseudo-TTY`, allowing you to directly interact with the container process instead of running it in the background.<br>

Creating both `lib` and `lib64` directories ensures compatibility with different library architectures and configurations in Linux systems. Some libraries and binaries might expect libraries in different directories based on system architecture.<br>

Each time you want to run a command that is not available by default, copy its libs and `bin` into the directory.<br>
