## Kubernetes

Kubernetes is a system that automatically manages, scales, networks, and maintains containers across many machines.

### 1. Why Kubernetes Exists

Containers alone are useful for:

- production apps
- development environments
- machine learning
- experiments
- backend services

But when applications become very large:

- many servers
- many containers
- scaling
- failures
- networking
- deployments

managing containers manually becomes extremely difficult.

This is where Kubernetes comes in.

### 2. What Is Kubernetes?

Kubernetes is a:

```text 
Container orchestration platform
```

Meaning:

> It manages large groups of containers automatically.

Kubernetes builds on top of containers.

So:

```text 
You must understand containers before learning Kubernetes
```

### 3. Kubernetes Nickname

Kubernetes is often shortened to: **`k8s`**

Why?

Because:

- K + 8 letters + s
- K ubernete s
- 12345678

### 4. What Problems Kubernetes Solves

Kubernetes helps with:

- scaling containers
- restarting crashed containers
- networking containers
- rolling updates
- load balancing
- scheduling containers across servers
- managing clusters

### 5. Fundamental Kubernetes Concepts

#### 5.1 Control Plane

The control plane is:

```text
The brain of the Kubernetes cluster
```

It coordinates everything.

Responsibilities:

- scheduling containers
- managing nodes
- monitoring cluster state
- handling deployments

Old name:

```text
Master node
```

New preferred name:

```text
Control plane
```

#### 5.2 Nodes

A node is:

```text
A machine that runs containers
```

A node can be:

- a VM
- a physical server
- another container

Not important what it physically is.

Think of it as:

```text
A destination where containers run
```

**Important note**

Kubernetes `node` is NOT:

- `Node.js`

They are completely different things.
`
#### 5.3 Pods

A pod is the smallest deployable unit in Kubernetes.

Think of a pod as:

```text
A wrapper around one or more containers
```

Containers inside the same pod:

- share networking
- share storage
- must run together

**Common setup**

Usually:

```text
1 container = 1 pod
```

Example:

| Pod | Container |
| --- | --- |
| API pod | Node.js app |
| Mongo pod | MongoDB |

**Why separate pods?**

Because they scale independently.

Example:

You may want:

- 10 API containers
- 1 MongoDB container

#### 5.4 Services

A service provides a stable way for pods to communicate.

**Problem:**

Pods constantly change.

When scaling:

- pods start
- pods stop
- IP addresses change

So relying on pod IPs is unreliable.

**Service solution**

A service acts like:

```text
A stable network endpoint
```

Example:

Instead of:

```text
Talk to pod IP 10.0.0.5
```

you say:

```text
Talk to the api-service
```

Kubernetes automatically routes traffic to available pods.

**Important idea**

You can have:

```text
1 container → 1 pod → 1 service
```

Very common beginner setup.

#### 5.5 Deployments

A deployment describes:

```text
The desired state of your application
```

Example:

I want:

- 3 API pods
- running Node.js app
- always alive

Kubernetes constantly works to maintain that state.

If a pod crashes:

✅ Kubernetes automatically replaces it.

### 6. Kubernetes Is Hard

Containers are considered the “easy” part.

Kubernetes is significantly more complex because it solves large-scale infrastructure problems.

This is normal.

### 7. Kubernetes CLI — kubectl

Main Kubernetes command line tool:

```text
kubectl
```

Used to:

- create deployments
- inspect clusters
- scale apps
- debug containers
- manage services

**Step 1 — Install `kubectl` (FIRST)**

You install the CLI tool on your system.

**Step 2 — Verify connection**

Run: 

```sh
kubectl cluster-info
```

Shows cluster information.

### 8. Running Kubernetes Locally

You need a local Kubernetes cluster for development.

Two common choices:

| Tool | Purpose |
| --- | --- |
| Docker Desktop Kubernetes | Easier |
| Minikube | More advanced/local cluster |

### 9. Docker Desktop Kubernetes

Docker Desktop includes built-in Kubernetes support.

Good for beginners.

**How to enable it**

**Step 1**

Open Docker Desktop

**Step 2**

Open Settings / Preferences

**Step 3**

Go to Kubernetes tab

**Step 4**

Enable Kubernetes

**Step 5**

Restart Docker Desktop

**Step 6**

Wait a few minutes

**Verify it works**

Run:

```sh
kubectl cluster-info
```

You should see:

- control plane
- cluster endpoints

### 10. Minikube

Minikube is another local Kubernetes tool.

More flexible than Docker Desktop.

Used only for local development.

**Start Minikube**

```sh
minikube start
```

### 11. Kubernetes Contexts

You can have multiple Kubernetes clusters installed.

Examples:

- Docker Desktop cluster
- Minikube cluster
- cloud cluster

These are called:

```text
contexts
```

### 12. Switching Contexts

Command:

```sh
kubectl config use-context minikube
```

or:

```sh
kubectl config use-context docker-desktop
```

Short version:

```sh
kubectl config use minikube
```
