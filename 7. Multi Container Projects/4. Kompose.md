## Kompose

Kompose takes a Docker Compose YAML file and translates it into Kubernetes configuration files, serving as a first step for developers to migrate their Docker Compose configurations to Kubernetes

Kompose bridges the gap between Docker Compose and Kubernetes by converting simple multi-container setups into full Kubernetes deployments.

### 1. What Problem Are We Solving?

We already have a working app:

- Node.js API
- MongoDB database
- React frontend

We previously used:

```text
docker-compose.yml
```

👉 This works for local development

But Kubernetes needs:

```text
YAML files for Pods, Services, Deployments
```

These are much more complex.

### 2. The Problem

If we write Kubernetes configs manually:

- too many files
- too much YAML
- easy to make mistakes

So we use a helper tool.

### 3. Introducing Kompose

**Kompose**

👉 Kompose converts:

```text
docker-compose.yml → Kubernetes YAML files
```

So instead of writing Kubernetes from scratch:

- ✔ You write Docker Compose
- ✔ Kompose converts it
- ✔ Kubernetes runs it

### 4. Why Kompose is useful

It helps you:

- start Kubernetes faster
- avoid writing complex YAML manually
- migrate from Docker Compose easily

### 5. Install Kompose

Example (Mac):

```sh
brew install kompose
```

### 6. Modify docker-compose.yml for Kubernetes

We slightly improve your Compose file so Kompose understands it better.

Final modified file:

```yaml
services:
  api:
    build: api
    ports:
      - "8080:8080"
    links:
      - db
    depends_on:
      - db
    environment:
      MONGO_CONNECTION_STRING: mongodb://db:27017
    labels:
      kompose.service.type: nodeport
      kompose.image-pull-policy: Never

  db:
    image: mongo:7
    ports:
      - "27017:27017"

  web:
    build: web
    links:
      - api
    depends_on:
      - api
    ports:
      - "8081:80"
    labels:
      kompose.service.type: LoadBalancer
      kompose.service.expose: true
      kompose.image-pull-policy: Never
```

### 7. What changed and why

#### 7.1 depends_on

```yaml
depends_on:
```

👉 Means:

> Start this container AFTER another container starts

Example:

- API waits for DB
- Web waits for API

#### 7.2 labels (VERY IMPORTANT for Kubernetes)

**API:**

```yaml
kompose.service.type: nodeport
```

👉 Means:

> Expose API inside cluster using NodePort

✔ Good for internal + scalable services

**Web:**

```yaml
kompose.service.type: LoadBalancer
```

👉 Means:

> Expose frontend to the outside world

This becomes your entry point.

**image pull policy**

```yaml
kompose.image-pull-policy: Never
```

👉 Means:

> Use local images, don’t try to download from Docker Hub

Important for local development.

#### 7.3 MongoDB port exposure

```yaml
ports:
  - "27017:27017"
```

Kubernetes needs explicit port definitions.

### 8. Convert Compose → Kubernetes

Run:

```sh
kompose convert --build local
```

What this does:

It generates files like:

- api-deployment.yaml
- api-service.yaml
- db-deployment.yaml
- web-service.yaml
- web-deployment.yaml

So now Docker Compose becomes Kubernetes YAML.

### 9. Apply to Kubernetes cluster

```sh
kubectl apply -f '*.yaml'
```

`kubectl`

👉 This tells Kubernetes:

> “Create everything defined in these YAML files”

### 10. What Kubernetes does now

After applying:

Kubernetes will:

- Create Deployments
- Create Pods
- Create Services
- Connect everything together
- Start running your app

### 11. Check everything is running

```sh
kubectl get all
```

You should see:

- pods → Running
- services → Active
- deployments → Available

### 12. Important statuses

**✔ Running**

Everything is working

**❌ ErrImagePull**

Means:

- image not found
- not built locally
- Kubernetes cannot access it

### 13. How traffic flows (VERY IMPORTANT)

After Kompose conversion:

```text
Browser → LoadBalancer (web)
        → API Service (NodePort)
        → DB Service
        → MongoDB Pod
```

### 14. Key architecture idea

You now have:

| World | Description |
| --- | --- |
| Docker Compose world | Single machine, simple orchestration |
| Kubernetes world | Cluster of machines, scalable system |

### 15. Final mental model

```text
docker-compose.yml
        ↓
kompose convert
        ↓
Kubernetes YAML files
        ↓
kubectl apply
        ↓
Cluster running your app
```
