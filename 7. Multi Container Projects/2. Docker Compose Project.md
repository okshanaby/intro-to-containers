## Docker Compose Project

### 1. What Problem Are We Solving?

We previously had:

- A Node.js backend
- A MongoDB database
- A React frontend

Each one needed its own container.

Running them manually with many `docker run` commands becomes annoying.

Docker Compose solves this by letting us define everything in one **YAML** file.

### 2. Create `docker-compose.yml`

In the root of the project:

```text
project/
│
├── api/
├── web/
└── docker-compose.yml
```

Add this:

```yaml
services:
  api:
    build: api
    ports:
      - "8080:8080"
    links:
      - db
    environment:
      MONGO_CONNECTION_STRING: mongodb://db:27017

  db:
    image: mongo:7

  web:
    build: web
    ports:
      - "8081:80"
```

### 3. Understanding services

```yaml
services:
```

This section defines all containers needed for the application.

Each service = one container.

In this app we have:

| Service | Purpose |
| --- | --- |
| api | Node.js backend |
| db | MongoDB database |
| web | React frontend |

### 4. The api Service

```yaml
api:
```

This creates the backend container.

#### Step 4.1 — `build: api`

```yaml
build: api
```

Meaning:

- Go into the `api/` folder
- Find the Dockerfile
- Build the image from it

Equivalent command:

```sh
docker build ./api
```

#### Step 4.2 — `ports`

```yaml
ports:
  - "8080:8080"
```

Format:

`HOST_PORT:CONTAINER_PORT`

Meaning:

`Computer port 8080 → Container port 8080`

So:

`localhost:8080`

opens the backend app.

#### Step 4.3 — `links`

```yaml
links:
  - db
```

This connects the `api` container to the `db` container.

The backend can now communicate with MongoDB using: `db` as the hostname.

So this works: `mongodb://db:27017`

Docker automatically creates networking between containers.

#### Step 4.4 — `environment`

```yaml
environment:
  MONGO_CONNECTION_STRING: mongodb://db:27017
```

Sets an environment variable inside the container.

Inside Node.js: `process.env.MONGO_CONNECTION_STRING`

returns: `mongodb://db:27017`

Used to connect to MongoDB.

### 5. The db Service

```yaml
db:
  image: mongo:7
```

This starts a MongoDB container using the official image from Docker Hub.

Equivalent command:

```sh
docker run mongo:7
```

#### Why No Dockerfile?

Because we are using a prebuilt image.

Docker downloads it automatically.

#### Why No Ports?

The database is only needed internally by containers.

The backend talks to MongoDB through Docker networking.

No need to expose MongoDB to your computer.

#### MongoDB Defaults

The MongoDB image already:

- exposes port 27017
- creates a volume for persistent data

So Docker keeps the database data between restarts.

### 6. The web Service

```yaml
web:
```

This is the frontend React app.

#### Step 6.1 — build: web

```yaml
build: web
```

Docker:

- enters web/
- finds the Dockerfile
- builds the frontend image

#### Step 6.2 — ports

```yaml
ports:
  - "8081:80"
```

Meaning:

`localhost:8081 → nginx container port 80`

So the frontend opens at:

`http://localhost:8081`

### 7. What Happens When We Run Compose?

Command:

```sh
docker compose up
```

Docker Compose will:

- Read docker-compose.yml
- Build the api image
- Build the web image
- Pull MongoDB image
- Create a network
- Connect containers together
- Start all containers

All with one command.

### 8. Why Docker Compose Is Useful

Without Compose we would manually run:

```sh
docker build
docker run
docker network create
docker run -p
docker run -e
```

many times.

Compose stores the entire setup in code.

This is called:

**Infrastructure as Code**


### 9 Updated Dockerfile for Development

#### 9.1 Add nodemone and run the server from it

Dockerfile:

```Dockerfile
FROM node:latest

RUN npm i -g nodemon

USER node

RUN mkdir /home/node/code

WORKDIR /home/node/code

COPY --chown=node:node package-lock.json package.json ./

RUN npm ci

COPY --chown=node:node . .

CMD ["nodemon", "index.js"]
```

#### 9.2 Add Volumes (Live Code Sync)
**Why this step is needed**

The Dockerfile alone is NOT enough for development.

Without volumes:

- code is copied once into container
- changes on your machine are NOT reflected
- nodemon won’t restart on edits

So we need **live syncing between local files and container**.

Add this to `docker-compose.yml`

```yaml
services:
  api:
    build: api
    ports:
      - "8080:8080"
    links:
      - db
    environment:
      MONGO_CONNECTION_STRING: mongodb://db:27017
    volumes:
      - ./api:/home/node/code
      - /home/node/code/node_modules

  web:
    build: web
    ports:
      - "8081:80"
```

### 9.3. What volumes do
API volume
- ./api:/home/node/code = hostPath:containerPath
- First part `./api` is host path
- Second part `/home/node/code` is container path

 Syncs your backend code live into container

Important extra volume (VERY IMPORTANT)
  
- /home/node/code/node_modules
  

Without it:

- your local folder overwrites container
- node_modules disappears
- app crashes with “Cannot find module”

What this line does:

It tells Docker:

> “Keep node_modules inside the container, don’t override it”

### 10. Rebuilding Containers

If you change Docker-related files:

```sh
docker compose up --build
```

This forces Docker to rebuild images.

Without `--build`, Docker may use old cached images.

### 11. Scaling Containers

Command:

```sh
docker compose up --scale web=10
```

This creates:

- 10 web containers
- running at the same time.
