## 2. Docker Images with Docker

### 1. Basic idea (super simple)
- **Image** → template (like Ubuntu, Alpine)
- **Container** → running instance of that image
- **`docker run`** → creates + starts a container

### 2. Run a container (interactive)
```sh
docker run --interactive --tty alpine:3.19.1
# docker run -it alpine:3.19.1 (short form)
```

**What happens:**
- Docker checks if image exists
- If not → downloads it
- Creates a container
- Opens a shell inside it

**Flags:**
- `-i` = interactive (keep input open)
- `-t` = terminal (nice shell display)

You now type inside the container
`exit` = stop container

### 3. Run a command instead of a shell
```sh
docker run alpine:3.19.1 ls
```

**What happens:**
- Start container
- Run `ls`
- Show output
- Container stops

No interaction, just runs and exits

### 4. Background (detached mode)
```sh
docker run --detach -it ubuntu:jammy
# docker run -dit ubuntu:jammy (shorter form)
```
It runs the container in the background and does not keep the terminal attached to the container's process

**Flags:**
- `-d` = detached (run in background)
- `-i` = keep input open
- `-t` = terminal

**What happens:**
- Container runs in background
- You get a long ID (container ID)

### 5. See running containers
```sh
docker ps
```

**Shows:**
- Container ID
- Name
- Status

### 6. Attach to a running container
```sh
docker attach <container_id>
```
Connects you to the container terminal
Like “jumping inside it”

### 7. Stop (kill) container
```sh
docker kill <container_id/s or container_name/s >
```
Immediately stops it

### 8. Give container a name
```sh
docker run -dit --name my-ubuntu ubuntu:jammy
```
**Flag:**
- `--name` = custom name

Now instead of ID:

```sh
docker kill my-ubuntu
```

### 9. Remove container
```sh
docker rm my-ubuntu
```

Deletes stopped container

### 10. Auto-delete container

```sh
docker run --rm -dit --name my-ubuntu ubuntu:jammy
```
**Flag:**
- `--rm` = remove container automatically after it stops

No need to manually clean up

### 11. Starting a new process inside the container
`docker exec` is a command that lets you run a new command inside an already running container.
- It does NOT start a new container.
- It does NOT restart anything.
- It just enters an existing container and executes a command there.

`docker exec` is NOT the same as `docker attach`, even though they feel similar.

**Simple idea first**
- `docker attach` → connect to the main process
- `docker exec` → start a new process inside the container

**Example step-by-step**
```sh
# 1. Start container in background
docker run -dit --name test ubuntu:jammy

# 2. Enter it using exec
docker exec -it test bash

# Now you're inside the container

# 3. Exit
exit
```
Container keeps running

**Difference: exec vs attach**
| Feature             | `docker attach` | `docker exec` |
| ------------------- | --------------- | ------------- |
| Connect to          | Main process    | New process   |
| Safe to use         | ❌ risky         | ✅ safe        |
| Multiple sessions   | ❌ no            | ✅ yes         |
| Can break container | ✅ yes           | ❌ no          |


**Real-world analogy**
Think of a container like a running car 🚗

- `docker attach` → you sit in the driver seat
- If you mess up → car stops
- `docker exec` → you open a new door and sit inside
- Car keeps running no matter what

### 11. Shows containers 
```sh
# 1. Running containers only 
docker container ls
# docker ps (short version)

# 2. Running, Stopped and Exited (all) containers 
docker container ls -a
# docker ps -a (short version)
```

Think: ***“What containers are currently alive?”***

**Output includes:**
- Container ID
- Image used
- Status
- Name
- Ports

### 12. Shows all downloaded images on your machine
```sh
docker image ls
```
Think: ***“What blueprints do I have stored?”***

**Output includes:**
- Image name (e.g. ubuntu, alpine)
- Tag (version like jammy, 3.19)
- Size

### 13. Deletes all stopped containers
```sh
docker container prune
```
Think: ***“Clean up old unused containers”***

**Important:**
- Only removes containers that are NOT running
- Does NOT touch images

**Example:**
If you ran 10 containers and stopped them → this removes them all

### 14. Cleans almost everything unused
```sh
docker system prune
```
Think: ***“Deep clean Docker system”***

**It removes:**
- Stopped containers
- Unused networks
- Dangling images
- Build cache

More aggressive version:
```sh
docker system prune -a
```
Also removes:
***Unused images*** (even downloaded ones not used by containers)

### 15 Removing Docker Images
```sh
docker rmi <image_name_or_id>
```
**What it means:**
- rmi = remove image
- It deletes the image (blueprint) from your machine.
