## 4. Tags
Tags allows you to run different versions of the same container, just like you can install React version 17 or React version 18: some times you don't want the latest. Let's say you have a legacy application at your job and it depends on running on Node.js 20 (update your app, Node.js is already past end-of-life)

### 1. “latest” tag (default version)
```sh
docker run -it node

# This is actually:
# docker run -it node:latest
```
**Meaning:**
- `latest` = default version
- Docker assumes it if you don’t specify a version

### 2. What is a tag?

A tag = version of the image

**Example:**

- node:latest → newest Node.js
- node:20 → Node.js version 20
- node:18 → Node.js version 18

**Why tags matter**
Sometimes you don’t want the newest version

**Because:**
- old apps may break
- company systems depend on specific versions

### 3. Running a specific version
```sh
docker run -it node:20 bash
```
**Meaning:**
- Start Node.js version 20
- Open a Linux terminal inside it

```sh
# Then:
node --version

# Output:
v20.x.x
```

### 4. Smaller Linux version (Alpine)
```sh
docker run node:20-alpine cat /etc/issue
```
**Meaning:**
- Node.js version 20
- BUT using a lighter Linux system (Alpine)

**Command	Meaning**
- `node`	latest version
- `node:latest`	same thing
- `node:20`	fixed version 20
- `node:20-alpine`	version 20 + lightweight Linux

One-line summary: ***Docker tags = “choose which version of the software you want”***
